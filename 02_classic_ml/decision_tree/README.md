## 结论

| 实验 | 结果 |
|---|---|
| iris,深度 3 | 5 个叶子,训练 0.9619,测试 0.9556 |
| iris,只用花瓣长宽,深度 4 | 训练 0.9905,测试 0.9778 |
| 手算花瓣长度上的最优切点 | gini 0.6667 降到 0.3333,切点 1.7 |
| 两类半月形数据(400 个,噪声 0.35) | 深度 2 到 4 测试 0.892,深度 15 训练 1.0、测试 0.792 |
| 后剪枝 | 不剪枝 47 个叶子 test 0.792,alpha=0.0069 剪到 7 个叶子 test 0.892 |
| 回归树(sin + 噪声) | 深度 2:mse 0.1821;深度 5:mse 0.0287 |

- 特征重要性上花瓣宽度 0.966、花瓣长度 0.034,两个萼片特征完全是 0。
- 树不需要标准化。分裂只比较大小,特征做线性变换不影响分裂结果。
- 过拟合在树上一眼就能看出来:训练集 1.0,测试集掉 10 个点。

## 踩坑

- 手算出来的最优切点是花瓣长度 1.7,sklearn 的根节点却是花瓣宽度 0.8,一开始以为算错了。实际上两种切法都把 setosa 完全分出去,加权 gini 都是 0.3333,属于并列最优,谁先被扫到就用谁。
- iris 太干净,树长到 4 层就不长了,想演示过拟合得换有噪声的数据。第一版用 iris 画深度曲线,四条线几乎重合,什么都看不出来。
- `cost_complexity_pruning_path` 返回的最后一个 alpha 会把树剪成只剩一个叶子,遍历时要切掉,不然图最后会掉到 0.5。
- `feature_importances_` 是训练集上的不纯度下降,偏向取值多的连续特征。萼片长度 0 不代表没用,只是这棵树没用它分裂。
- 树的边界是轴对齐的矩形,数据斜着排就很吃亏。换成月牙形数据,深度再大也只能堆台阶。
- 剪枝的 alpha 用单次测试集挑会有波动,实际应该配合交叉验证。
